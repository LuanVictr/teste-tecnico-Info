# Implementation Plan: Aivacol Fleet Management Backend

**Branch**: `001-fleet-management-backend` | **Date**: 2026-06-05 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `specs/001-fleet-management-backend/spec.md`

---

## Summary

Build a production-grade NestJS 10+ backend for Aivacol's Fleet Management module. Core deliverables: JWT auth, CRUD for models and vehicles (with mandatory Redis cache + pagination + filters), Swagger, Docker Compose, Jest tests. Bonus: brands, users, RabbitMQ events, MongoDB audit, multistage Docker build. Deploy target: Hostinger VPS via Docker Compose.

---

## Technical Context

**Language/Version**: TypeScript / Node.js 18+

**Primary Dependencies**:
- `@nestjs/core`, `@nestjs/common` v10+
- `@nestjs/typeorm` + `typeorm` + `mssql`
- `@nestjs/jwt` + `@nestjs/passport` + `passport-jwt`
- `@nestjs/cache-manager` + `cache-manager-redis-yet` + `ioredis`
- `class-validator` + `class-transformer`
- `@nestjs/swagger`
- `bcrypt`
- (Bonus) `@nestjs/microservices` + `amqplib` + `@nestjs/mongoose` + `mongoose`

**Storage**:
- SQL Server (primary — TypeORM, migrations)
- Redis (cache — vehicle queries)
- MongoDB (bonus — audit logs)

**Testing**: Jest + `@nestjs/testing` + Supertest (integration)

**Target Platform**: Linux server (Hostinger VPS) via Docker Compose

**Project Type**: REST API (NestJS monolith)

**Performance Goals**: Cache hit on vehicle reads within same TTL window (SC-003)

**Constraints**: `synchronize: false` always; all routes JWT-protected by default; cache TTL configurable via env; audit non-blocking

**Scale/Scope**: Single-tenant fleet management; no concurrency concerns at this scale

## Architecture Decisions (from research.md)

| Decision | Choice | Rationale |
|----------|--------|-----------|
| Global JWT guard | APP_GUARD + @Public() | Zero chance of unprotected route |
| Cache key | Alphabetically sorted query string | Deterministic, no key mismatch |
| Cache invalidation | Pattern delete vehicles:list:* | Mutations affect all paginated views |
| Redis adapter | cache-manager-redis-yet | Most maintained NestJS v10 adapter |
| Seed strategy | OnModuleInit idempotent check | Zero-touch startup, satisfies SC-001 |
| RabbitMQ transport | @nestjs/microservices | First-class NestJS support |
| Dockerfile | 2-stage alpine + non-root | Minimal image, security best practice |
| SQL Server healthcheck | sqlcmd SELECT 1 | Prevents app crash on slow DB init |

## Migration Plan

Order of TypeORM migrations:
1. `CreateUsersTable`
2. `CreateBrandsTable` (FK to users)
3. `CreateModelsTable` (FK to brands, users)
4. `CreateVehiclesTable` (FK to models, users) + indexes on model_id and year
5. `SeedAdminUser` (idempotent insert of aivacol user)
